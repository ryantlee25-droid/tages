## Platform

web

## Users

**Primary: engineers on Ryan's Mersive team**, onboarding onto Tages and using it daily. They arrive already told to use it, not needing to be sold. Their job on this site is to understand what it is, get installed, join the shared project, and trust that it works.

**Secondary: technically literate people Ryan points at the site** to evaluate the work. They are judging whether this is serious engineering. They are not a signup funnel.

The site is explicitly **not** currently optimized for cold self-serve acquisition.

## Product Purpose

AI coding agents forget everything between sessions, so every decision gets re-litigated, every convention re-explained, and past mistakes repeated by the next agent touching the same code. Tages gives agents persistent, shared memory about a codebase.

Success is a teammate installing it, joining the team's project, and having their agent recall a colleague's memory without being walked through it.

## Positioning

**Memory as a team practice, not personal storage.** Personal memory tools store facts for one developer who remembers what they stored. Tages treats codebase memory as a managed artifact shared across a team: structured types, quality scoring, audit trails, and sharpen passes that rewrite vague notes into imperative agent instructions. One developer's architecture decision becomes every agent's context.

**Zero local dependencies for semantic search.** Embeddings are generated by a hosted endpoint Tages runs, so semantic search works with nothing installed locally. No Ollama, no API key, no configuration. This also makes the vector space uniform across a team by construction rather than by convention, which is a correctness property and not only a convenience: mixing embedding models silently produces confident nonsense.

## Operating Context

- Developers work in their own repositories, in a terminal and in an AI coding agent.
- Agents connect over **MCP** (Model Context Protocol). Claude Code is the primary client; Cursor, Codex, and Gemini are supported.
- Memory is bound **per directory**, via `tages link` writing a `.tages/config.json` marker and an `.mcp.json` in that repo. Resolution walks up to the git root. One repo maps to one project by default; several repos can share one project.
- Onboarding is: install the CLI, change into your own work repo, `tages link --project-id <uuid>`, restart the agent.
- Joining a teammate's project requires an invite from an owner or admin. A plain `member` can read but cannot write.
- A web dashboard exists for browsing and editing memories, managing team members, and finding the project ID.

## Capabilities and Constraints

- **56 MCP tools** (20 available on the free tier; 36 more on paid). Counted from the running server's `tools/list`, not from documentation.
- **42 top-level CLI commands.** Counted from the built binary's own `--help`. Earlier marketing copy claiming 53 was wrong and must not be reused.
- **67 Postgres migrations** covering schema, row-level security, RPCs, and indexes.
- Storage is Supabase Postgres with pg_trgm trigram search and pgvector semantic search, plus a local SQLite cache for low-latency reads.
- Search is hybrid: trigram, semantic, temporal, and chunk-level channels fused with Reciprocal Rank Fusion.
- If the hosted embedding endpoint is unreachable, recall degrades to trigram matching rather than failing. It never silently substitutes a different embedding model.
- Install is `npm install -g @tages/cli`. The MCP server runs via `npx -y @tages/server`.
- Auth is Supabase Auth with GitHub OAuth. RBAC is owner/admin write, member read-only, enforced at the database layer by RLS.
- Optional AES-256-GCM field-level encryption exists but has **no key-distribution mechanism**, so it is unsuitable for teams today and must not be presented as a team feature.
- MIT licensed. Self-hosting against your own Supabase is supported.

- The name is **Tages**, after the Etruscan divine child who dictated sacred knowledge to scribes.
- Voice is direct and technical. The audience is engineers who dislike being marketed to.
- The live site is `tages.ai`; the application is served at `app.tages.ai`.
- **Standing visual preference (confirmed 2026-08-16): the developer-infrastructure convention, played straight.** Ryan asked for the marketing surface to sit alongside **Supabase** and **Stripe/Resend**, and their craft level is the bar. Nothing else about the previous marketing look is preserved.

## Product Principles

1. **Claim only what has been counted or run.** Prior copy carried a wrong command count and a stale test badge. Every number on this site must trace to an artifact.
2. **The visitor is an engineer being onboarded, not a lead being converted.** Getting them installed and joined beats persuasion.
3. **Team correctness is the differentiator.** Shared memory that silently diverges is worse than no shared memory; say so plainly.
4. **Zero local setup is the newly-won property.** It is the most concrete thing that changed and the easiest to verify.
5. **Do not oversell what is unfinished.** Encryption lacks key distribution; the harness captures telemetry that does not become recallable memory. Neither belongs in a feature list.
